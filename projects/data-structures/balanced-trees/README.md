# balanced-trees

> Versão em português: [README.pt-BR.md](README.pt-BR.md)

Three search trees with the same interface, written in C++ and in Java: an unbalanced binary search tree, an AVL tree and a red-black tree. It teaches how an unbalanced tree degenerates into a list when the keys arrive sorted, and how rotations prevent it. A static page replays the insertion of a fixed sequence and shows every rotation.

Full explanation: [docs/en/data-structures/balanced-trees.md](../../../docs/en/data-structures/balanced-trees.md).

## Quiz topics it demonstrates

- `data-structures` / `binary-search-trees`: the ordering property, insertion, removal in three cases, and degeneration with sorted keys.
- `data-structures` / `avl-trees`: balance factor, single and double rotations, rebalancing after insertion and removal, height bound.
- `data-structures` / `red-black-trees`: the colour rules, insertion as a red node, recolouring with a red uncle, rotations with a black uncle, comparison with AVL.
- `data-structures` / `binary-trees-and-traversals`: height, and the in-order traversal as the test of the search property.

## Run

The only requirement is Docker.

```sh
./setup-unix-balanced-trees.sh        # Linux and macOS
./setup-windows-balanced-trees.ps1    # Windows
```

The script builds one pinned image per language and runs the tests in each. The C++ image checks the format with clang-format when the tests run. The Java image checks the format with Spotless (google-java-format) while it is built, which is the only step that needs the network, and compiles with `javac -Xlint:all -Werror`.

## Structure

| Path | Content |
| --- | --- |
| `cpp/search_tree.hpp`, `java/src/SearchTree.java` | the common interface: insert, remove, contains, size, height, rotation counter, invariant check |
| `cpp/bst.hpp`, `java/src/Bst.java` | unbalanced tree, written with loops so that a 100,000-level tree does not overflow the call stack |
| `cpp/avl.hpp`, `java/src/AvlTree.java` | AVL tree |
| `cpp/red_black.hpp`, `java/src/RedBlackTree.java` | red-black tree with a NIL sentinel |
| `cpp/steps.hpp`, `java/src/Steps.java` | records one frame per change for the visualiser |
| `cpp/demo.cpp`, `java/src/Demo.java` | the demo: height table and visualiser data |
| `dashboard/` | the static rotation visualiser |
| `results/heights.md` | committed height and rotation table |

## Tests

```sh
docker compose run --rm cpp-test
docker compose run --rm java-test
```

- **Property tests**: for each tree and 3 seeds, 6,000 random inserts, removals and searches are compared with the ordered set of the language (`std::set`, `TreeSet`). The invariant of the tree is checked after **every** operation: key order for all three, balance and stored heights for AVL, root colour, no red-red pair and equal black heights for red-black.
- **Sorted insertion of 100,000 keys**: the unbalanced tree reaches height 100,000 with 0 rotations. The AVL tree reaches height 17 and the red-black tree height 31, both under 40. Then half of the keys are removed from the balanced trees and the invariants still hold.
- **Visualiser data**: the recorded frames contain one frame per inserted key and exactly one frame per rotation counted.

The C++ and Java programs produce byte-identical visualiser data and height tables.

## Demo

```sh
docker compose run --rm cpp-test tree_demo heights
docker compose run --rm java-test java -cp /opt/classes Demo heights
```

Prints the height and the number of rotations of the three trees after sorted and after random insertion of 1,000 to 100,000 keys. Committed output: [results/heights.md](results/heights.md).

## Rotation visualiser

Open `dashboard/index.html` in a browser, straight from disk. Choose a tree, then use Next, Previous, Play or the slider to replay the insertion of 10, 20, 30, 40, 50, 60, 55, 25, 22, 5, 7, 45. Each rotation and each recolouring is one step. The page uses a committed CSS file and no network.

The data file is generated by the implementation, then formatted with Biome like every script of the repository:

```sh
docker compose run --rm cpp-test tree_demo steps > dashboard/steps.js
bunx biome format --write dashboard/steps.js
```

`dashboard/tailwind.css` was built from `dashboard/input.css` with the Tailwind CSS 4.3.3 CLI that the repository installs for `tools/scaffold`. Rebuild it only when the classes used by the page change.
