# orm-vs-sql

> Versão em português: [README.pt-BR.md](README.pt-BR.md)

What does an ORM cost, and what SQL does it really send? This mini-project writes the same five queries three times, with raw SQL (node-postgres), Prisma and Drizzle, on one PostgreSQL schema. The tests prove that the three return identical rows, capture the SQL each one generates and commit it next to the query, and a benchmark measures the latency of each approach and the cost of the N+1 pattern.

Code: MP-TX-3. Full explanation: [docs/en/transactions/orm-vs-sql.md](../../../docs/en/transactions/orm-vs-sql.md).

## The five queries

| Query | What it exercises | Code | Captured SQL |
| --- | --- | --- | --- |
| `author-by-id` | Lookup by primary key | [ts](ts/src/queries/author-by-id.ts) | [sql](ts/src/queries/author-by-id.captured.sql) |
| `top-posts` | Filter, sort, limit | [ts](ts/src/queries/top-posts.ts) | [sql](ts/src/queries/top-posts.captured.sql) |
| `posts-with-author` | Join | [ts](ts/src/queries/posts-with-author.ts) | [sql](ts/src/queries/posts-with-author.captured.sql) |
| `post-count-by-author` | Aggregate with `GROUP BY` | [ts](ts/src/queries/post-count-by-author.ts) | [sql](ts/src/queries/post-count-by-author.captured.sql) |
| `add-post-with-comment` | Transaction with two inserts | [ts](ts/src/queries/add-post-with-comment.ts) | [sql](ts/src/queries/add-post-with-comment.captured.sql) |

The N+1 example and its fix are in [n-plus-one.ts](ts/src/queries/n-plus-one.ts), with the captured SQL of the [naive](ts/src/queries/n-plus-one-naive.captured.sql) and the [fixed](ts/src/queries/n-plus-one-fixed.captured.sql) versions.

## Quiz topics it demonstrates

- `transactions` / `acid-properties`: atomicity of a multi-statement transaction, and why every statement must go through the transaction handle (`tx`)

The other lessons of this mini-project (generated SQL, N+1, cost of an abstraction) belong to the `databases` and `performance` quiz areas.

## Run

The only requirement is Docker.

```sh
./setup-unix-orm-vs-sql.sh        # Linux and macOS
./setup-windows-orm-vs-sql.ps1    # Windows
```

The script builds the image, runs the tests against a PostgreSQL container on an internal network, and removes the containers at the end. The tests rewrite the `*.captured.sql` files.

## Benchmark (the demo)

```sh
docker compose run --rm bench
docker compose down -v
```

Rewrites `results/` and the two tables above.

## Tests

```sh
docker compose run --rm ts-test
docker compose down -v
```

The container runs the TypeScript type check and then `bun test`.

## Structure

| Path | What it is |
| --- | --- |
| `ts/sql/schema.sql` | The schema and the seed data, shared by the three approaches |
| `ts/prisma/schema.prisma`, `ts/src/drizzle-schema.ts` | How Prisma and Drizzle describe the same tables |
| `ts/src/context.ts` | The three clients, each with a recorder of the SQL it sends |
| `ts/src/queries/` | One file per query with the three implementations, and the captured SQL next to it |
| `ts/src/bench.ts` | The benchmark |
| `results/` | The committed results |
